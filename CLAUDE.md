# PortaSnap: notes for Claude

Build, test and release recipes, decisions and gotchas, kept in the repo so every computer has them.

PortaSnap lives at `%USERPROFILE%\Music\Claude\Projects\PortaSnap` (project `src\PortaSnap`, solution `PortaSnap.slnx`). Started 2026-10-18; v0.1.0 delivered. User asked for a Snagit recreation that is local, offline and fully portable (carry between PCs).

- Clean-room build: Snagit was NOT decompiled. REA was used only to reverse the `.snagx` file format (ZIP + JSON + PNG) from the user's own files; findings in `docs\SNAGX-FORMAT.md`. Keep it that way.
- Target `net8.0-windows10.0.19041.0` (WinRT needed for MP4 recording via MediaTranscoder), WPF + WinForms (tray/ColorDialog only). `GlobalUsings.cs` adds System.IO (WPF implicit usings lack it) → use `System.Windows.Shapes.Path` explicitly.
- Portable data: `PortaSnap-Data\` next to the exe (settings.json, Library\*.psnap/*.mp4, log); LocalAppData fallback if read-only.
- Versioning now follows the global CLAUDE.md setup (since 2026-10-27): bump `<Version>` in the csproj (+ app.manifest where present) and add a CHANGELOG entry, then `.\publish.ps1`, which refuses an already-archived version and keeps `<Exe>.exe` at the project root plus `Versions\Archive\<Exe>-<version>.exe`; commit, push, and `gh release create v<version> <Exe>.exe`. `archive-version.ps1` is gone (git holds the source history; old snapshot folders sit in `Versions\Archive`).
- Verification recipe: CLI `--export <in> <out.png>` renders .snagx/.psnap headlessly (compare to the snagx's own thumbnail.png); `--record x,y,w,h secs out.mp4` tests the encoder. UI smoke via PrintWindow + UI Automation — the PowerShell harness must call SetThreadDpiAwarenessContext(-4) or captures are cropped (user's monitors are 175%/200%). Delete `dist\PortaSnap-Data` after smoke tests.
- Hotkeys use a WH_KEYBOARD_LL hook that ignores injected keys, so automation can't trigger Print Screen; drive captures via the panel's Capture button instead.
- Theming (v0.2.0): palette = merged dictionary 0 (`Themes\Light.xaml`/`Dark.xaml`, swapped by `ThemeManager`), stock-control templates in `Themes\Controls.xaml`. Always use `DynamicResource`/`SetResourceReference` for brushes — StaticResource won't follow theme switches. User's Windows shows accent colour on title bars, so DWM dark title bars stay blue.
- "Start with Windows" writes HKCU Run `PortaSnap` = `"<exe>" --tray`, re-pointed each launch while enabled. The user runs their real copy from `dist\` (their data lives in `dist\PortaSnap-Data`) — never delete it; smoke-test with the bin\Debug exe and throwaway data instead, and restart their dist copy afterwards (publish kills it).
- Editor interaction can be smoke-tested by driving the real mouse/keyboard (SetCursorPos + mouse_event, SendKeys) against the bin\Debug exe, reading results from the editor title ("name — W × H"); restore the cursor afterwards. Python edit scripts with lots of quotes break bash heredocs — write them to the scratchpad and run the file.
- SendKeys "{DELETE}" sent right after a WPF ContextMenu closes never reaches the app (harness quirk, not an app bug); use raw keybd_event(0x2E) for Delete in smoke tests.
- Destructive edits (crop/resize/canvas/slice) call `RememberOriginal()` so Revert can restore `original.png`; undo history is per capture (`_histories` in EditorWindow), lost only when the editor closes.
- Library layout (v0.5+): each capture = image file in `Library\` (JPG default, user picks format/quality) + project `Library\.projects\<name>.psnap`. `LibraryItem.Path` = the image (user-facing file ops), `ProjectPath` = identity matched against `SnapDocument.LibraryPath`; `LibraryStore.Save` writes project + rewrites the image. Old .psnap-in-root libraries auto-migrate; the user's pre-migration copy is in `dist\PortaSnap-Data\Backup-0.4-Library`.
- When smoke-testing with a copy of the user's settings, force `startWithWindows=false` and `startInTray=false` (otherwise the Run key gets re-pointed at the debug exe / no panel appears). SendKeys also loses Ctrl+S after a mouse drag — use raw keybd_event or UIA Invoke.
- User's PC has UAC off (EnableLUA=0): Explorer runs with an admin token and ignores HKCU\Software\Classes associations, so .psnap is also registered in HKLM\Software\Classes. My tool shell can't write HKLM even unsandboxed ("access not allowed"), but anything launched via `explorer.exe "<path>"` (exe or .cmd) gets full rights — use that to relaunch the user's PortaSnap after publishing (a Start-Process child of my shell is restricted) and to run `PortaSnap.exe --associate`. Test Explorer behaviour with UIA Invoke on the Explorer list item (scratchpad explorer-test.ps1), not Start-Process.
- User's 26 Snagit captures (Documents\Snagit) contain no annotations — import = background PNG only.
